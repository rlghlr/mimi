Product Design Spec · v1.0 · 2026.08

뷰티 모델과 아티스트를
잇는 양면형 마켓플레이스

Muse는 뷰티 모델·고객과 뷰티 전문가를 연결하는 양면형 매칭 플랫폼입니다. 핵심은 단순 예약이 아니라 탐색 → 지원·제안 → 대화 → 매칭 → 예약 → 시술 → 리뷰 → 재매칭 퍼널을 최대한 짧게 만드는 것입니다. 이 문서는 착수 전 13개 항목의 설계 근거를 정리합니다.

브랜드 Muse (독자 브랜드 · 미몽 자산 미복제) 플랫폼 Mobile-first · Web Responsive 스택 Next.js · Supabase · PostgreSQL 권한 CUSTOMER / PROFESSIONAL / ADMIN
01

서비스 전체 구조

Muse에는 두 방향의 매칭이 동시에 존재합니다. 전문가가 모델을 찾는 모델 모집형과, 고객이 시술·고민을 올리고 전문가가 제안하는 고객 요청형입니다. 두 퍼널 모두 채팅에서 수렴해 매칭·예약·리뷰로 이어집니다.

A · 모델 모집형 (Pro가 모델을 찾음)
전문가 모집 공고→ 모델 공고 탐색→ 지원→ 지원자 확인→ 채팅→ 매칭 확정→ 시술→ 리뷰
B · 고객 요청형 (Customer가 전문가를 찾음)
고객 상담 등록→ 전문가 상담 확인→ 제안 발송→ 제안 비교→ 채팅→ 전문가 선택→ 예약→ 시술→ 리뷰
두 퍼널은 채팅(chats)에서 하나로 합류합니다. 채팅 하단 CTA만 [매칭 확정](모집형) 또는 [예약하기](요청형)로 달라지며, 이후 예약·시술·리뷰·재매칭 흐름은 공통입니다. 수익화(크레딧·프리미엄 노출·빠른 매칭)는 전문가의 노출 단계에 부착됩니다.

02

권한 모델 — CUSTOMER / PROFESSIONAL / ADMIN

Role 기반(RBAC)으로 페이지·기능·데이터 접근을 제한합니다. Supabase의 Row Level Security(RLS)로 DB 레벨에서 강제하고, 프론트에서 라우트 가드로 이중 보호합니다.

03

05

User Flow

상태(state)를 명시적으로 관리해 각 전이 지점에서 알림·예외처리를 건다. 핵심 3개 플로우.

① 지원 → 매칭 recruit_applications.status

지원완료→ 확인중 (Pro 열람)→ 채팅중→ 매칭확정 또는 미선정

② 예약 reservations.status

예약요청→ 전문가확인→ 예약확정→ 방문예정→ 시술완료 이탈 예약취소 노쇼

③ 고객 요청형 전체 여정

상담 등록→ 전문가 열람→ 제안 수신(N)→ 제안 비교→ 채팅→ 전자동의→ 예약→ 시술완료→ 리뷰→ 재매칭
각 → 전이마다 notifications 이벤트가 발생하고(§17), 동시에 KPI 퍼널 이벤트(§13)가 로그로 적재됩니다. 상태 전이는 서버(RPC/Edge Function)에서만 허용해 클라이언트 위변조를 차단합니다.

08

MVP 개발 범위

"동작하는 마켓플레이스"를 1차에서 완성합니다. 회원가입·DB·지원·매칭·채팅·Admin이 실제로 돌아가는 것이 1차 목표.

MVP 1차 · 코어 매칭
  • 회원가입 / C·P 구분 / 프로필
  • 전문가 프로필 · 운영자 승인
  • 모델 모집 공고 등록·목록·상세
  • 지원 · 지원자 관리 · 매칭
  • 실시간 1:1 채팅
  • 알림 · 마이페이지
  • Admin(회원·공고·승인)
MVP 2차 · 요청형 & 신뢰
  • 고객 상담 · 전문가 제안·비교
  • 전문가 검색 · 상세(4탭)
  • 예약 (상태머신)
  • 리뷰 (완료건 한정)
  • 찜 · 신고/차단
  • 전자 초상권 동의
  • Admin 매칭·신고 관리
MVP 3차 · 수익화
  • Muse Credit 충전
  • 프리미엄 공고 · 상단 노출
  • 빠른 매칭(급구)
  • 광고 상품
  • 결제(PG) · 환불
  • 리뷰 특가
확장 로드맵(범위 외): 프로용 뷰티 제품 커머스 · 뷰티 구인구직 · 교육 · 뷰티샵 B2B · 창업 서비스. 데이터 구조는 확장을 막지 않도록 설계.
